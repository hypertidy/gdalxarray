# gdalxarray site

Source of https://hypertidy.github.io/gdalxarray/, a [Quarto](https://quarto.org)
website whose pages execute on every build.

## Layout

| Path | What |
|------|------|
| `_quarto.yml` | site config, navigation, quartodoc sections |
| `_common.py` | helpers every page imports: fixtures, store registry, liveness |
| `_pre_render.py` | fetches wxylib/fixtures at the pinned commit into `_fixtures/` |
| `stores.yml` | every remote store the site reads, with its permanence |
| `index.qmd`, `install.qmd`, `changelog.qmd` | front pages (the last two include `../INSTALL.md` and `../CHANGELOG.md`) |
| `guide/` | offline examples on pinned fixtures; they assert against GDAL oracles |
| `gallery/` | examples against public cloud stores, guarded by the store check |
| `stores.qmd` | the registry and last check, rendered |
| `reference/` | generated by quartodoc (not committed) |
| `sst-analysis.md` | parked draft, not rendered |

## Two kinds of example

**Guide pages** use only [wxylib/fixtures](https://github.com/wxylib/fixtures)
at the commit in `_common.py` / `_pre_render.py` (`FIXTURES_SHA`). They must
pass: a failed assertion fails the build. To move to newer fixtures, change
the SHA in both files.

**Gallery pages** read remote stores. Each store has an entry in
`stores.yml`; `scripts/check_stores.py` opens each with GDAL and writes
`_stores_status.json`; a page runs its remote cells only when `live(key)` is
true, and those cells use `error: true` so a mid-read failure shows the error
rather than breaking the build. In CI each gallery page is rendered on its own
by `scripts/render_gallery.py` under a hard time limit (a GDAL read blocked in
libcurl cannot be interrupted from Python); a page that overruns is rendered
again with its remote cells off. The gallery uses `freeze: auto`, so the full
`quarto render` afterwards reuses those results. To add one: add a `stores.yml` entry, then use
`status_callout(key)` and `if live(key):` in the page, with the address as a
literal string and a hidden `assert dsn == store(key)["dsn"]`.

## Build locally

With a GDAL that has Python bindings (conda-forge shown):

```sh
micromamba create -n gxdocs -c conda-forge python=3.12 gdal libgdal-netcdf libgdal-hdf5 \
  libgdal-arrow-parquet xarray dask matplotlib pandas pyyaml jupyter quarto
micromamba activate gxdocs
pip install -e .. "quartodoc" "griffe<2"

python ../scripts/check_stores.py   # optional: without it, gallery cells skip
python -m quartodoc build
python ../scripts/render_gallery.py # gallery pages, one at a time, time-limited
quarto preview
```

conda-forge GDAL does not include Icechunk support, so the Icechunk gallery
page skips there; the CI image (`ghcr.io/hypertidy/gdal-r-python`) has it when
GDAL is built with it. Set `GDALXARRAY_DOCS_OFFLINE=1` to skip every remote
cell.
